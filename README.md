# 诺阿计划人物卡

Python桌面人物卡编辑器 · 早期原型 v0.3（NDSL与可视化技能编辑基础版）

## 启动

用VS Code打开本文件夹，运行 `main.py`，或在终端执行：

```powershell
& C:\Python312\python.exe .\main.py
```

从GitHub下载或克隆后，使用包含Tkinter的Python 3.12，并安装图片处理依赖：

```console
python -m pip install -r requirements.txt
python main.py
```

原开发机的离线版本在 `.deps` 中预备了Pillow；这个目录不提交到GitHub。已拥有该目录时可直接使用，其他环境按上述方式安装依赖。如果本机Python缺少pip或Tcl/Tk，请先使用Python安装器修复相应组件。

若Python提示找不到Tcl/Tk，启动程序会从当前标准库目录寻找匹配组件。`python main.py --check-runtime` 可创建窗口后立即关闭，检查运行环境。解释器启动时的 `<prefix>` 警告来自本机Python安装路径，建议使用Python安装器修复；不影响已验证的本机窗口启动。


## 新增：NDSL与可视化技能编辑

从 **晶灵 → 天赋衍生 → 技能 / 定义词 / 规则流程** 进入新系统。原有天赋衍生长文本仍可编辑；这里是新建的独立技能系统，不是恢复旧技能表。

- 管理多项技能的名称、ID、主动/被动/反应/常驻类别、说明、消耗、冷却及图绑定。
- 使用表单或NDSL注册静态定义词、自定义声明式节点；共享定义词、模板和公共规则图。
- 独立Canvas编辑窗口支持节点搜索/拖放、类型连线、断线、参数、平移缩放、框选、复制粘贴及撤销重做。
- 独立Python引擎可模拟事件、条件、计算、状态/资源操作、技能可用性、顺序控制、临时变量和子图。
- 技能资源随人物卡JSON保存/打开，应用更改后参与自动草稿和原有备份；未应用的编辑可整体取消。
- 不将模拟变化写回当前人物卡公式或资源。消耗/冷却说明也不会被默认为自动结算。

**体验示例：**进入技能管理器，点击“载入完整示例”，在“模拟与日志”中连续使用三次 `skill.pressure`，观察压抑转换为恐惧并解锁技能。点击“应用到人物卡”后再保存。

[完整使用教程与NDSL示例](docs/NDSL.md) · [模块架构、边界与后续待办](docs/SKILL_ARCHITECTURE.md)

可直接打开 [示例人物卡](examples/NDSL技能示例人物.json)，或在资源管理器导入 [示例资源包](examples/NDSL技能资源.json)。

## 本次修改

1. 默认保存、另存为、导出、自动草稿统一使用UTF-8 `.json`。照片也是JSON内嵌数据。XML已停用；按用户要求不提供旧文件迁移。
2. 证件照支持JPEG、PNG、WebP、BMP、GIF（取首帧）。点击“上传图片并裁剪”，拖动5:7裁剪框并调整滑块，确认后生成240×336 PNG。删除源照片后，人物卡仍保留证件照。
3. 第一版技能表及其属性计算已退出运行；新增技能系统见上文，不与旧表混用。开发描述字段已删除。原始代码封存在 `noah/archive`，不被应用导入执行。
4. 属性一为12个基础选项；属性二额外包含生命、情绪、社会、语言、概念。
5. 活跃度、烈性、适配度分别具有独立“方向”下拉框与非负数值输入；能量等级只有数值。公式按需要恢复符号，灵能总等级仍对活跃度和烈性取绝对值。
6. 晶灵、展开、过载及背景页的长文本支持独立滚动条、鼠标滚轮、扩展/收起、放大编辑。放大窗口使用“应用并关闭”提交修改，“取消”放弃本次修改。
7. 展开和过载使用加大的启用控件，支持点击整个标签区域切换。
8. 背景页全部文本栏（包括学术经历）统一使用新版编辑器。
9. 装备槽仅剩赋能笔与蓄能器、抑制器、变形重组器、中枢核心；先装备赋能笔才可安装部件。

## 使用与文件

- 人物属性页可填写基础与补正，种族骰需手动投掷。计算结果只读。
- 背包点击格子添加物品，点击物品编辑位置和尺寸；支持旋转占格、安全箱和腰带。
- 正式保存覆盖前保留 `.bak` 上一版本，亦可通过“打开”读取备份，再另存为JSON。
- 编辑期间每30秒将有效数据保存为 `.local/recovery.json`；“恢复草稿”可恢复最近一次有效草稿。自动草稿不能代替正式保存。
- 未保存修改在关闭、新建或打开另一份文件时会提醒。
- Ctrl+S保存，Ctrl+O打开，Ctrl+N新建。

## 数据边界与扩展

文件版本为2、规则版本为0.2-provisional。模型与公式位于 `noah/domain.py`，文件读写位于 `noah/storage.py`，照片处理位于 `noah/photos.py`，长文本与裁剪控件位于 `noah/widgets.py`。
文本每栏最多30000字，人物卡上限2MB，上传图片上限20MB/2500万像素。证件照标准化后清除原始元数据并内嵌为PNG，程序不根据人物卡内容读取外部图片路径。不执行人物卡内的代码、公式、XML或对象反序列化。

`extensions` 为未来扩展保留JSON兼容对象；有类型、长度及嵌套深度限制。数值字段保留稳定路径，方便后续接入公式。

具体计算和待定规则见 `RULES.md`。界面仍为早期原型，尚无拖拽、打印或exe打包。职业点上限与等级/SP等待规则补充。

## 排版与装备槽修正

属性总览使用八列固定表格；属性来源表增加适应当前字体的行高、固定最小列宽、加粗表头和交替底色，窄窗口支持横向滚动。按钮、分页、区块标题、提示文字统一使用蓝灰与青绿色样式。

装备槽是独立的单件容器：点击槽位直接创建或编辑，不要求背包内存在对应物品；没有坐标、宽高、旋转和堆叠输入。装备只在槽位内显示，不出现在背包/安全箱/腰带的随身物品列表。随身物品编辑器也不再提供移入装备的选项。每个槽位可清空，赋能笔仍受部件先清空的约束。总重量包含随身物品及独立装备各一次。

当前完整测试86项通过（74项核心测试、12项窗口测试）。
