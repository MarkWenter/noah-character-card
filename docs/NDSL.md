# NDSL 与天赋衍生技能编辑器

本模块是增量加入的独立技能系统，不恢复 `noah/archive` 中的旧技能代码，也不改写现有人物属性公式。人物卡原有“天赋衍生”文字完整保留。

## 最快体验完整案例

1. 运行 `main.py`，打开“晶灵”页，滚动到“天赋衍生”。
2. 点击“技能 / 定义词 / 规则流程”。
3. 点击“载入完整示例”。它只替换本编辑窗口的技能资源；应用前可以取消，原有天赋衍生文字不变。
4. 打开“模拟与日志”，选择 `skill.pressure`，点击“连续使用三次”。
5. 目标B先获得1、2层压抑；第三次移除压抑并获得1层恐惧，`恐惧共鸣`从锁定变为可用。摘要及日志显示结果。
6. 在“定义词ID”填 `status.fear`，点击“移除指定状态”。恐惧共鸣重新锁定。
7. 回到“规则图”，选择“压抑转为恐惧”，点击“编辑流程”查看实际节点和连线。
8. 在技能管理器点击“应用到人物卡”，回主窗口保存JSON。重新打开后所有资源与图位置均保留。

也可以从主程序直接打开 `examples/NDSL技能示例人物.json`，或在技能管理器导入 `examples/NDSL技能资源.json`。运行时状态、事件和日志仅存在于模拟副本，不自动写入人物卡。

## 编辑提交和取消

资源表单“保存”只更新技能管理窗口中的草稿；流程窗口“保存规则图”同样只更新这份草稿。
技能管理窗口的“应用到人物卡”提交全部技能资源，使主窗口变为未保存状态，并纳入原有自动保存、正式保存和备份流程。
“取消本次编辑”或关闭技能管理窗口会放弃整次编辑；子窗口“取消”只丢弃该子窗口本次更改。不要在未应用时关闭编辑器期待自动草稿记录这些临时更改。

## 从头创建压抑机制

### 1. 注册静态定义词

点击“批量NDSL声明”，输入以下内容后注册：

```text
定义词 压抑:
    ID: status.suppression
    类型: Status
    分类: 负面, 精神
    数据类型: Integer
    默认值: 0
    最小值: 0
    最大值: 3
    可叠加: true
    可驱散: true

定义词 恐惧:
    ID: status.fear
    类型: Status
    数据类型: Integer
    默认值: 0
    最小值: 0
    最大值: 1
    可叠加: false
```

可在“定义词”列表搜索、编辑名称、改ID、查看引用或删除。改ID会更新明确的结构化ID引用；不会擅自改写说明文字或表达式中的文本。仍被其他资源使用时，必须先解除引用才能删除。

定义词类别支持 Attribute、Resource、Status、Tag、Entity、Event、Scene、DamageType、Custom。数据类型为 integer、number、boolean、string、object。属性和资源首版只接受数值类型；状态只接受非负整数层数。

NDSL使用每级4个空格缩进，不接受Tab或重复字段。字段值可以是JSON值，裸文本也可作为文本值；分类支持逗号分隔。结构化字段可写在“字段”中，每个字段具有数据类型、默认值及可选最小/最大值。定义词不允许执行条件、监听器或 `expr` 动态对象。

### 2. 创建公共转换规则图

在“规则图”新建一张 `shared` 图，点击“编辑流程”。从节点库添加：

| 节点 | 参数 |
|---|---|
| 状态变化 | definition = status.suppression |
| 读取状态 | definition = status.suppression，target = target |
| 数值比较 | b = 3，op = >= |
| 移除状态 | definition = status.suppression |
| 施加状态 | definition = status.fear，value = 1 |

连接：

- 状态变化的 `out` → 数值比较的 `in`（执行流）。
- 读取状态的 `value` → 数值比较的 `a`（数据流）。
- 数值比较的 `true` → 移除状态的 `in`。
- 移除状态的 `out` → 施加状态的 `in`。

保存规则图。达到3层时转换为恐惧的逻辑属于这张图，定义词中没有任何转化特判。

### 3. 创建并绑定技能

在“技能”新建 `skill.pressure`，名称“施压”，类型 `active`。描述、消耗、冷却均可填写，图可以先留空。
选中该技能，点击“编辑流程”。添加“技能使用”与“施加状态”节点，后者设置 `status.suppression` 和 `value=1`。把前者 `out` 接到后者 `in`，保存时自动建立图绑定。

没有图的技能是合法的纯文本技能。空图或缺少必要参数的图可以保存为草稿；节点编辑器“验证”会列出待完善项目，实际运行错误会在模拟中报告。

技能的 `enabled` 为是否参与模拟；`initially_available` 为模拟开始时的可用性。动态解锁只修改运行时可用性，不改变技能原始定义。消耗和冷却当前是说明信息；需要执行的资源消耗应在规则图中明确编排。

### 4. 添加动态解锁规则

新建另一个技能，初始可用设为false。公共图监听 `status.fear` 的状态变化，读取层数并与0比较；`true` 连接“技能可用性”节点（enabled=true），`false` 连接另一个（enabled=false），两者指定同一个技能ID。

## 画布操作

- 左侧输入名称、ID或类别搜索；双击或按“添加选中节点”添加，也可拖入中央画布。
- 拖动节点头部移动。空白处拖动框选；Shift可追加选择。
- 点击输出端口，再点击输入端口；也可按住输出端口拖到输入端口连接。
- 白色端口/浅色连线为Flow执行流；蓝色端口/连线为Data数据流。
- 右键连线断开；右键空白取消待连接端口。
- 中键拖动平移，鼠标滚轮缩放，“适应画布”查看整图。
- 选中节点后右侧编辑参数；切换节点时应用上一节点参数，也可按“应用参数”。
- Delete删除，Ctrl+C/Ctrl+V复制粘贴，Ctrl+Z/Ctrl+Y撤销重做；快捷键在画布获得焦点时生效。
- 复制使用此编辑窗口内的剪贴板，包含所选节点及内部连线，不覆盖操作系统剪贴板。
- 导入/导出规则图JSON保留图结构与位置；导入时沿用当前图ID，以免破坏技能绑定。
- 保存前自动检查端口类型、引用、重复输入及直接循环。一个数据输入仅允许一个来源。
- “测试当前图”在独立副本中触发第一个事件入口；连续点击复用测试状态，改图后自动重置。完整技能与公共图联动建议用管理器的“模拟与日志”。

## 参数与表达式

参数可直接输入数字、ID、文本；对象和布尔值使用JSON。需要动态数值时加 `=` 前缀：

```text
=自身.力量 * 0.3
=目标.生命值 / 目标.最大生命值
=变量['charge']
```

“计算表达式”节点的 `expression` 参数直接填写表达式文本，不加前缀：`a * 0.3`。
允许加减乘除、整除、取余、比较、布尔运算、条件表达式，以及min/max/abs/round/floor/ceil；不支持赋值、列表推导、指数、任意函数调用、导入或Python对象访问。Percent与Number兼容，不自动把30转换为0.3；倍率30%应填0.3。

`自身`、`来源`、`目标`对应只读运行时实体视图；`事件`包含事件ID、来源、目标、data等上下文。实际七项人物属性通过现有 `domain.calculate` 取得，不建立第二套基础属性公式。HP/MP/TP来自当前人物卡，生命值/最大生命值提供中文别名。
自定义Attribute/Resource定义的默认值可在模拟中使用；定义名“魔法攻击力”可通过 `自身.魔法攻击力` 读取。它是自定义模拟字段，不会偷偷变成现有人物属性公式。

## NDSL自定义节点

自定义节点只能基于固定的内置操作声明，不接受任意Python代码。例如：

```text
定义节点 生命比例判定:
    ID: node.hp_ratio_check
    模板: 数值比较
    类型: Condition
    输入:
        执行: Flow
        目标: Entity
        阈值: Percent
    左值: 目标.生命值 / 目标.最大生命值
    比较: <=
    右值: 阈值
    输出:
        成立: Flow
        不成立: Flow
```

注册后它会出现在节点库中，可搜索、添加、连线和复用。模板表单可以配置端口字典与JSON默认参数，NDSL页可以直接编辑声明。“表单 → NDSL”用于同步显示；保存采用当前页内容。

## 公共子图

在规则图中声明 `inputs` 与 `outputs` 接口，然后通过“子图输入”和“子图输出”节点读写命名数据，用“调用公共子图”节点调用。调用节点的 `args` 是名称→值的JSON对象，名称需与子图声明一致。

接口和数据流类型必须一致。通用调用节点返回Any；需要将结果接入Number等严格输入时，可在模板编辑器基于 `control.call` 创建输出类型为Number的专用模板。Any不会被自动猜测为数字。

首版支持手动创建可复用子图及命名接口；尚未提供框选后一键抽取子图、动态展开调用端口或批量跨图重构。

## 执行范围与限制

已实现基础事件、比较/布尔/标签判断、属性/资源/状态读取、表达式与随机/骰子、状态施加/移除与持续时间、资源修改/伤害/治疗、技能可用性、顺序/终止、子图调用、临时变量以及规则图开关。
共享图和场景图采用同一执行结构；场景图没有自动地图生命周期，需要手动启停。

首版不提供真实计时延迟、任意次数循环、召唤实体效果、多目标选择、完整事件取消/替代结算、规则包依赖管理或正式战斗回合调度。运行时保留召唤物扩展位置，未将其宣称为可执行召唤功能。
所有状态修改经统一接口产生后续事件；默认最多256个事件、2048个节点求值、24层事件/子图深度。超限或异常会回滚本次调用的全部状态和随机数状态，保留错误日志。

原有人物卡版本仍为2；没有 `talent_derivations` 的人物卡会补充空资源库。模块自身版本为1。人物卡和资源包仍受2MB限制，单图导入/导出为500KB；每图最多256节点、512连线，不允许直接回边循环。回调链与战斗日志只属于模拟，不自动持久化。
