# 技能系统技术说明

## 方案选择

本次在现有Tkinter程序内采用Canvas节点编辑器，并将文档操作、声明解析、图验证与执行引擎全部独立组织。没有新增运行依赖。

评估结果：

| 路线 | 本项目的取舍 |
|---|---|
| Tkinter Canvas | 与现有启动、弹窗和本地JSON保存一致；无需额外Web服务或浏览器桥接。首版选择此方案。|
| 成熟Python节点库 | 多数方案需要额外GUI运行栈；本轮没有为了节点页迁移主程序。未来可通过图文档模型替换展示层。|
| WebView + 前端节点组件 | 可在后续提升大图交互，但会引入桥接、打包与前端构建流程。本轮不引入。|

Canvas是实际可编辑视图，支持拖放与连线，不是静态示意图。节点运行不依赖Tkinter，测试可直接调用引擎。

主程序只增加天赋衍生入口和新数据字段。`domain.calculate`不依赖新引擎，不把模拟效果回写人物公式。

## 持久化结构

人物卡顶层新增可选 `talent_derivations`：

```json
{
  "version": 1,
  "definitions": [],
  "node_templates": [],
  "shared_rules": [],
  "skills": []
}
```

原有人物卡版本仍为2，原晶灵天赋衍生文本保持原字段。加载缺少新字段的v2人物卡时补充空资源库；不恢复或迁移归档的第一版旧技能代码。

`shared_rules`是所有规则图的统一集合，由kind区分skill/shared/scene；技能通过graph_id引用。图包括id/name/kind/enabled、命名inputs/outputs、nodes和edges。
节点采用id/template/params/position；连线采用from=[节点ID,端口名]、to=[节点ID,端口名]、kind=flow或data。
定义词和模板为静态资源；运行时实体、状态、临时变量、事件队列和日志独立于文件资源。

所有正式人物卡保存继续使用既有大小限制、原子替换与备份。资源包独立JSON及单图JSON也使用有界读取和原子写入。编辑器维护草稿事务，只有“应用到人物卡”才影响主程序的dirty、保存与自动草稿。

## 图和表达式语义

- Flow决定执行先后；Data按需计算，同一张图的一次调用内缓存已求得的输出。
- 条件节点沿true/false（或成立/不成立）分支执行。
- 顺序节点先完整执行first分支，再执行second分支。相同目标经多条执行路径可被执行多次，次数受步数限制。
- 一个数据输入只能连接一个来源；一个执行输出可分叉。数据输入未连线时使用参数或对应基础默认值。
- 图禁止直接循环；子图引用禁止直接/间接递归。事件连锁允许，但有数量和深度限制。
- Any不自动当成Number；子图需要具体数值输出时可声明专用调用模板的输出类型。Percent在首版是数值接口，不隐式转换百分数。
- 参数中的 `{"expr":"..."}` 为安全表达式；表单可用=前缀生成该对象。计算节点expression字段为普通表达式文本。
- 表达式只读取字典视图，不允许Python对象属性、导入、文件访问、任意调用、指数、赋值或推导式。round位数限制为-12～12。
- 定义词内部拒绝动态expr对象以及事件/执行字段。静态描述中的普通文字不作为程序执行。
- 模板只能选择已实现的内置op，可通过默认参数、表达式及端口声明复用操作，不运行外部Python。

## 运行模型

`entity_from_card`通过既有domain.calculate读取七项最终属性与资源上限，通过body读取当前HP/MP/TP。返回深复制的运行时实例。Attribute和Resource定义可补充自定义模拟字段。

Runtime维护实体属性、资源、最大值、状态层数、时长、技能可用性、标签，以及全局临时变量、事件追踪与日志。召唤物只预留存储扩展点，首版没有生成效果。

Engine使用自己的资源副本；事件过滤器按事件类型、定义词和技能ID匹配。启用的shared/scene图响应事件；skill图须由角色持有并启用对应技能。

状态操作遵循定义词的层数上下限及stackable标记，改变后产生status_applied/status_removed/status_changed事件；不发生变化时不产生重复事件。正duration按目标的turn_ended事件递减，为0表示持续存在。
资源操作遵循上下限；整数资源拒绝小数结果。HP伤害/治疗以当前资源和既有上限处理，产生hp_changed、damage_resolved、entity_died等事件。

dispellable在本轮是静态标记，尚无单独“驱散”操作；remove_status表示显式移除，不自动视作驱散判定。

一次公开操作（use_skill、emit、apply_status或remove_status）是一笔模拟事务。异常或超限时恢复实体、图开关、临时变量、队列追踪和随机数状态，并追加错误日志。连续使用三次是三笔事务；某次失败不撤销前面已经完成的使用。

初始随机种子为0，可由API指定。默认预算：256事件、2048节点求值、24层事件/子图深度；日志最多2000条，事件历史最多1024条，临时变量最多128个。
